# Web Design System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install Tailwind CSS v4 and shadcn-vue into `apps/web`, wire up the Baituna color tokens (light + dark) and typography, and add the baseline set of shadcn-vue components every later frontend module will build on.

**Architecture:** Tailwind v4 is added via its Vite plugin (no `tailwind.config.js` — v4 configures through CSS `@theme`). shadcn-vue's CLI scaffolds `components.json`, a `lib/utils.ts` helper, and copies component source directly into `components/ui/` (not an npm dependency — the components become part of this repo and are edited freely). Dark mode uses `@nuxtjs/color-mode`, which toggles a `dark` class on `<html>`; Tailwind v4's `@custom-variant dark` is configured to key off that class instead of `prefers-color-scheme` alone, so a user's explicit toggle overrides their OS setting. Fonts load via `nuxt.config.ts` `app.head.link`, not a CSS `@import`, matching how Nuxt already manages head tags in this repo.

**Tech Stack:** Nuxt 4 (still using the pre-`app/` srcDir layout — `app.vue` and `pages/` live at `apps/web/` root, not `apps/web/app/`; this plan does not migrate that), Tailwind CSS v4, shadcn-vue 2.8, Reka UI, `@nuxtjs/color-mode`, TypeScript strict.

**Spec:** `docs/superpowers/specs/2026-08-23-baituna-design-system.md`. Background: `docs/superpowers/specs/2026-08-23-baituna-modules-design.md`, `docs/baituna-prd.md`.

## Global Constraints

- **Five colors only, each with one job.** Primary (emerald), secondary (bronze — accent/fill only, never text on light backgrounds), destructive (maroon), background, foreground. Do not invent a sixth. (Spec §2.5)
- **Never hardcode a hex color in a `.vue` file.** Always reference the Tailwind token (`bg-primary`, `text-muted-foreground`, etc.). Hardcoding breaks dark mode silently. (Spec §2)
- **Two type families only: Inter Tight (display) and Inter (body/data).** No third family, no per-page font swaps. (Spec §3.1)
- **Numeric data always gets `tabular-nums`.** Distances, coordinates, dates, counts — via the `.tabular-nums` utility class or `font-variant-numeric: tabular-nums`. (Spec §3.3)
- **shadcn-vue components are copied into this repo, not installed as a dependency.** Once added via the CLI, `components/ui/*.vue` is ordinary project code — edit it directly, don't wrap it. (Spec §4.1)
- **Spacing and layout use unmodified Tailwind defaults.** No custom spacing scale, no custom breakpoints. If a task below doesn't specify a Tailwind class, use the standard one. (Spec §4.2)
- **TypeScript is strict.** No `any`.
- **Commit messages follow Conventional Commits** (`feat:`, `chore:`, `docs:`) — commitlint + husky enforce this on commit.
- **Every command in this plan runs from `apps/web/`** unless stated otherwise.

### Task 2: Color tokens, dark mode, and fonts

- [ ] **Step 1: Install color-mode**

```bash
npm install @nuxtjs/color-mode@4.0.1
```

- [ ] **Step 2: Register the module and set the class strategy**

In `apps/web/nuxt.config.ts`, add `'@nuxtjs/color-mode'` to `modules` and a `colorMode` block:

```typescript
  modules: ['@nuxt/eslint', '@nuxtjs/color-mode'],
  colorMode: {
    classSuffix: '',
    preference: 'system',
    fallback: 'light',
  },
```

`classSuffix: ''` makes the module add a bare `dark` class to `<html>` (instead of `dark-mode`), which is what Task 2 Step 4's Tailwind variant expects.

- [ ] **Step 3: Write the token stylesheet**

Create `apps/web/assets/css/tailwind.css`. Every hex value here is copied verbatim from spec §2.3–2.4 — do not adjust any of them.

```css
@import "tailwindcss";

@theme {
  --font-display: "Inter Tight", system-ui, -apple-system, sans-serif;
  --font-sans: "Inter", system-ui, -apple-system, sans-serif;
  --radius: 0.625rem;
}

@custom-variant dark (&:where(.dark, .dark *));

:root {
  --background: #F7F4EE;
  --card: #FFFDF9;
  --foreground: #1F1D18;
  --muted-foreground: #655F53;
  --border: #E4DDCE;
  --border-strong: #D2C8B3;

  --primary: #0F5132;
  --primary-foreground: #FFFDF9;
  --primary-soft: #DAE8DF;

  --secondary: #C9A227;
  --secondary-foreground: #6B5312;
  --secondary-soft: #F3E7C6;

  --destructive: #7B1830;
  --destructive-foreground: #FFFDF9;
  --destructive-soft: #F0DADF;
}

.dark {
  --background: #1A1712;
  --card: #221E18;
  --foreground: #EFEAE0;
  --muted-foreground: #A29A8B;
  --border: #332E26;
  --border-strong: #453E33;

  --primary: #2E9E68;
  --primary-foreground: #0B1710;
  --primary-soft: #1B3A2A;

  --secondary: #D8B14A;
  --secondary-foreground: #E3C169;
  --secondary-soft: #3A2F16;

  --destructive: #D2647C;
  --destructive-foreground: #1A0A0F;
  --destructive-soft: #3B1C25;
}

@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-card: var(--card);
  --color-card-foreground: var(--foreground);
  --color-muted-foreground: var(--muted-foreground);
  --color-border: var(--border);
  --color-border-strong: var(--border-strong);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-primary-soft: var(--primary-soft);
  --color-secondary: var(--secondary);
  --color-secondary-foreground: var(--secondary-foreground);
  --color-secondary-soft: var(--secondary-soft);
  --color-destructive: var(--destructive);
  --color-destructive-foreground: var(--destructive-foreground);
  --color-destructive-soft: var(--destructive-soft);
}

body {
  background-color: var(--background);
  color: var(--foreground);
  font-family: var(--font-sans);
}
```

The `:root` block is the light palette by default — this matches the spec's stance that light is the base and dark is the explicit override, and it means an un-toggled page (before `@nuxtjs/color-mode`'s script runs) still renders correct light colors instead of unstyled ones.

The `@theme inline` block is what makes `bg-primary`, `text-muted-foreground`, etc. exist as Tailwind utilities — it maps Tailwind's color namespace onto the CSS variables defined above, so switching `.dark` on `<html>` repaints every utility without any component code changing.
