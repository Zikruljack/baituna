# MVP v2: Public Registration, Admin Dashboard, Multi-Friday Scheduling — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make mosque registration public (no login required, auto-creates
the submitter's account), give `super_admin`/`mosque_admin` a real
sidebar-based dashboard instead of the shared public header, and let mosque
admins assign Khatib/Imam/Muazzin for any upcoming Friday via a calendar
instead of only the single next Friday.

**Architecture:** Backend: one new nullable column (`mosques.friday_prayer_time`),
`POST /mosques` becomes auth-optional and creates a `public_user` account
inline when no token is present, `PATCH /mosques/:id` accepts the new prayer
time field. Frontend: a new `layouts/admin.vue` (sidebar) replaces the shared
`AppHeader`/`AppFooter` on every admin-only page; role-based redirect after
login; the registration form drops its auth requirement and gains
email/password fields; the Friday-schedule tab in the mosque management page
is rebuilt around a new `calendar` shadcn-vue component.

**Tech Stack:** Nuxt 4 (Nitro server routes), Drizzle ORM + Postgres, Zod,
Vue 3 `<script setup>`, shadcn-vue (Reka UI) + Tailwind v4, Vitest.

**Spec:** `docs/superpowers/specs/2026-08-25-baituna-mvp-v2-design.md`
(delta spec — also depends on the still-valid parts of
`docs/superpowers/specs/2026-08-25-baituna-web-ui-design.md`, specifically
§2.1 API type layer conventions and §4.3 the public `/masjid/[id]` page,
which this plan does not touch).

## Global Constraints

- Backend code lives under `apps/web/server/**` — this plan's backend tasks
  (1-6) touch only that tree; frontend tasks (7-16) touch `apps/web/pages`,
  `apps/web/layouts`, `apps/web/composables`, `apps/web/components`,
  `apps/web/types`, `apps/web/middleware`.
- `latitude`/`longitude` are validated and stored as **strings** matching
  `^-?\d{1,3}\.\d{1,7}$`, never numbers — see `server/utils/validation.ts`
  `latitudeSchema`/`longitudeSchema`. Do not change this for any task here.
- `assignmentDate` is always a `YYYY-MM-DD` string, never a `Date` object,
  at every layer (DB column is `date`, but Drizzle returns/accepts it as
  string here — see existing `AssignmentInput`).
- All new/changed Zod schemas live in `server/utils/validation.ts`, next to
  the existing ones — do not create a second validation file.
- Every mutating service function wraps its work in `db.transaction()` and
  calls `withAudit()` for the audit trail — follow the exact pattern already
  used in `mosque.service.ts`'s `createMosque`/`approveMosque`.
- Money/whitespace rule inherited from the existing codebase: two-space
  indent, single quotes, semicolons (Prettier config already enforces this
  via `npm run lint` — do not hand-format differently).
- DB-backed tests use `describe.runIf(Boolean(process.env.DATABASE_URL))(...)`
  exactly like `mosque.service.test.ts` and `friday-assignment.service.test.ts`
  — do not add a mocking layer for the database.
- This session's working agreement is **plans/specs only** — this plan is
  written for a separate execution agent to run; do not start implementing
  from this session.

```ts
export async function createMosque(
  db: Database,
  input: CreateMosqueInput,
  actorId: string | null,
): Promise<CreatedMosque> {
  return await db.transaction(async (tx) => {
    let createdBy = actorId;
    let newAccount: CreatedMosque['newAccount'];

    if (createdBy === null) {
      if (!input.submitterName || !input.email || !input.password) {
        throw createError({
          statusCode: 422,
          statusMessage: 'submitterName, email, and password are required to register without an account',
        });
      }

      const existing = await findUserByEmail(tx, input.email);
      if (existing) {
        throw createError({
          statusCode: 409,
          statusMessage: 'Email sudah terdaftar. Masuk ke akun Anda lalu ajukan pendaftaran masjid dari sana.',
        });
      }

      const passwordHash = await hashPassword(input.password);
      const [insertedUser] = await tx
        .insert(users)
        .values({
          name: input.submitterName,
          email: input.email,
          passwordHash,
          provider: 'local',
          role: 'public_user',
        })
        .returning();
      if (!insertedUser) throw new Error('Failed to create submitter account');

      createdBy = insertedUser.id;
      newAccount = {
        id: insertedUser.id,
        name: insertedUser.name,
        email: insertedUser.email,
        role: 'public_user',
      };
    }

    const [inserted] = await tx
      .insert(mosques)
      .values({
        name: input.name,
        address: input.address,
        latitude: input.latitude,
        longitude: input.longitude,
        cityId: input.cityId,
        provinceId: input.provinceId,
        status: 'pending',
        createdBy,
      })
      .returning();

    if (!inserted) throw new Error('Failed to create mosque');

    await withAudit(tx, {
      table: mosques,
      tableName: 'mosques',
      recordId: inserted.id,
      action: 'CREATE',
      actorId: createdBy,
      oldData: null,
      newData: { name: inserted.name, address: inserted.address, status: inserted.status },
      currentHistory: inserted.history as unknown[],
    });

    return { id: inserted.id, name: inserted.name, status: 'pending', newAccount };
  });
}
```

export interface OwnedMosque {
  id: string;
  name: string;
  address: string;
  fridayPrayerTime: string | null;

/** Returns the single mosque this user administers, or null. Relies on the "one account, one mosque" invariant — never returns more than one row. */
export async function findMosqueByAdminUserId(
  db: Database,
  userId: string,
): Promise<OwnedMosque | null> {
  const rows = await db
    .select({
      id: mosques.id,
      name: mosques.name,
      address: mosques.address,
      fridayPrayerTime: mosques.fridayPrayerTime,
    })
    .from(mosques)
    .where(and(eq(mosques.adminUserId, userId), isNull(mosques.deletedAt)))
    .limit(1);

  return rows[0] ?? null;
}
